# app-migration Specification

## Purpose
Путь миграции существующего Struts 1 приложения на движок через стартер: минимальный набор шагов для рабочей миграции, проверенный демо-приложением с аннотациями и набором тестовых приложений; руководство по миграции, матрица совместимости и инфраструктура публикации артефактов.

## Requirements

### Requirement: Миграция приложений на стартер
Приложения из набора тестовых приложений проекта SHALL запускаться через стартер: каждое приложение стартует свою Spring Boot конфигурацию (класс приложения), движок конфигурируется авто-конфигурацией стартера, а не ручным импортом. Вся функциональность приложений — страницы, формы, валидация, tiles, сообщения, upload — SHALL сохраниться без изменений struts-config.xml и JSP. Интеграционные тесты приложений SHALL выполняться на реальном embedded Tomcat против собранного стартера.

#### Scenario: Набор приложений на стартере
- **WHEN** собранный стартер подключён к каждому тестовому приложению и приложения разворачиваются на embedded Tomcat
- **THEN** каждое приложение стартует через авто-конфигурацию стартера и все его интеграционные сценарии проходят

#### Scenario: Полнота функциональности после миграции
- **WHEN** приложение мигрировано на стартер и прогоняются его интеграционные тесты
- **THEN** сценарии страниц, форм, валидации, tiles и сообщений дают те же результаты, что до миграции

### Requirement: Демо-миграция с аннотациями
Демо-приложение SHALL работать как исполняемое Spring Boot приложение без web.xml: миграция выражается заменой зависимости на `spring-struts1-starter`, подключением стартера и аннотациями `@StrutsAction`/`@StrutsForm` над экшенами и формами. Аннотированные экшены SHALL быть singleton-бинами Spring с внедрением зависимостей, аннотированные формы — prototype-бинами; остальная конфигурация — struts-config.xml, JSP, message-resources — SHALL работать как раньше.

#### Scenario: Запуск демо как Boot-приложения
- **WHEN** демо-приложение запускается как Spring Boot приложение (встроенный контейнер)
- **THEN** страницы рендерятся, формы заполняются и валидируются, сообщения резолвятся по локали, форварды работают

#### Scenario: Аннотированные бины в демо
- **WHEN** экшен и форма демо помечены `@StrutsAction`/`@StrutsForm`, а экшен объявляет зависимость через `@Autowired`
- **THEN** экшен — singleton, переиспользуется между запросами, зависимость внедрена; каждый запрос получает отдельный экземпляр формы

### Requirement: Руководство по миграции
Проект SHALL содержать руководство по миграции, описывающее все известные ручные шаги: замену артефакта Struts 1 на зависимости движка, подключение стартера, аннотации над формами и экшенами, типовые правки (Jasper для JSP, свойства стартера, статические ресурсы) — со ссылкой на демо-приложение как на эталон.

#### Scenario: Миграция по руководству
- **WHEN** разработчик выполняет шаги руководства для своего приложения
- **THEN** ни один необходимый шаг не отсутствует в руководстве, и каждый типовой ручной шаг задокументирован

### Requirement: Матрица совместимости
Проект SHALL публиковать матрицу совместимости: поддерживаемые версии Spring Boot (4.0.x), Java (17+), версии Spring Framework, контейнер сервлетов (Tomcat 11, jakarta servlet 6.1) и состав модулей со своими артефактами.

#### Scenario: Выбор версий по матрице
- **WHEN** разработчик выбирает версии для миграции своего приложения
- **THEN** матрица в документации однозначно задаёт поддерживаемые версии Boot, Java и контейнера

### Requirement: Инфраструктура публикации
Репозиторий SHALL содержать готовую к использованию инфраструктуру публикации Maven-артефактов: профиль публикации с настройкой целевого репозитория через свойства и документацию по запуску deploy. Инфраструктура SHALL проверяться локальной публикацией в файловый репозиторий; внешний канал публикации (учётные данные, репозиторий) SHALL быть задокументирован как настраиваемый снаружи репозитория.

#### Scenario: Локальная публикация артефактов
- **WHEN** запускается публикация профилем в файловый репозиторий
- **THEN** все модули публикуются со своими POM и доступны для подключения зависимостью

#### Scenario: Подключение опубликованных артефактов
- **WHEN** внешнее приложение подключает опубликованные артефакты движка и стартера
- **THEN** зависимости резолвятся и приложение собирается
