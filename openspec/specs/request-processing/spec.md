# request-processing Specification

## Purpose

Маршрутизирует запросы на экшены Struts по суффиксному маппированию и воспроизводит жизненный цикл запроса Struts 1 — populate → validate → execute → forward — с семантикой форвардов и форм.

## Requirements

### Requirement: Суффиксная маршрутизация экшенов
Запрос к экшену SHALL маршрутизироваться по пути без суффикса: запрос `/x.do` обрабатывается маппингом с `path="/x"`. Суффикс SHALL настраиваться; при смене настроенного суффикса маршрутизация выполняется по нему.

#### Scenario: Запрос по суффиксу .do
- **WHEN** поступает запрос `GET /Welcome.do` и в конфигурации зарегистрирован маппинг `path="/Welcome"`
- **THEN** запрос обработан этим маппингом

#### Scenario: Настроенный суффикс
- **WHEN** суффикс настроен как `.act` и поступает запрос `GET /Welcome.act`
- **THEN** запрос обработан маппингом `path="/Welcome"`

### Requirement: Незарегистрированный путь возвращает 404
Запрос к пути, для которого нет зарегистрированного маппинга, SHALL дать ответ 404.

#### Scenario: Неизвестный экшен
- **WHEN** поступает запрос `GET /Nope.do` и маппинг `/Nope` не зарегистрирован
- **THEN** клиент получает ответ 404

### Requirement: Populate формы из параметров запроса
Если маппинг объявляет форму, её свойства SHALL быть заполнены параметрами запроса по семантике commons-beanutils до вызова экшена; маппинг без формы SHALL обрабатываться без populate.

#### Scenario: Параметры заполняют свойства формы
- **WHEN** поступает POST с параметрами, имена которых совпадают со свойствами формы, объявленной в маппинге
- **THEN** к моменту вызова экшена свойства формы содержат значения параметров

#### Scenario: Маппинг без формы
- **WHEN** маппинг не объявляет атрибут `name` с формой
- **THEN** populate не выполняется и экшен вызывается сразу

### Requirement: Размещение формы по scope
Форма SHALL размещаться в области, заданной атрибутом `scope` маппинга (request или session), под именем form-bean из конфигурации.

#### Scenario: Форма в request
- **WHEN** маппинг объявляет `scope="request"` и форма создана для запроса
- **THEN** форма доступна последующей странице как атрибут запроса

#### Scenario: Форма в session
- **WHEN** маппинг объявляет `scope="session"` и форма создана для запроса
- **THEN** форма доступна как атрибут сессии и сохраняется между запросами в пределах сессии

### Requirement: Валидация по флагу validate
При `validate="true"` валидация формы SHALL выполняться до экшена: обнаруженные ошибки приводят к переходу на страницу `input` без вызова экшена, а ошибки SHALL быть доступны в запросе. При `validate="false"` валидация SHALL не выполняться.

#### Scenario: Ошибки валидации уводят на input
- **WHEN** маппинг объявляет `validate="true"` с `input="/pages/Input.jsp"` и метод validate формы вернул ошибки
- **THEN** экшен не вызывается, клиент получает страницу `input`, а ошибки доступны в запросе

#### Scenario: Успешная валидация
- **WHEN** маппинг объявляет `validate="true"` и validate формы вернул без ошибок
- **THEN** экшен вызывается после валидации

#### Scenario: Валидация отключена
- **WHEN** маппинг объявляет `validate="false"`
- **THEN** validate формы не вызывается и экшен выполняется

### Requirement: Выполнение экшена и форвард
Результат метода execute экшена SHALL управлять переходом: возвращённый форвард рендерится клиенту; маппинг с атрибутом `forward` или `include` SHALL обрабатываться как прямой переход на указанный ресурс без вызова экшена.

#### Scenario: Форвард из execute
- **WHEN** execute экшена возвращает форвард с `path="/pages/Done.jsp"`
- **THEN** клиент получает содержимое ресурса по этому пути

#### Scenario: Маппинг с атрибутом forward
- **WHEN** маппинг объявляет `path="/Welcome"` с `forward="/pages/Welcome.jsp"` и не объявляет тип экшена
- **THEN** запрос обрабатывается переходом на `/pages/Welcome.jsp` без вызова метода экшена

### Requirement: Локальные форварды приоритетнее глобальных
При совпадении имени локальный форвард маппинга SHALL использоваться вместо глобального форварда с тем же именем.

#### Scenario: Конфликт имён форвардов
- **WHEN** глобальный и локальный форварды объявлены с одинаковым именем, и экшен возвращает форвард по этому имени
- **THEN** используется путь локального форварда

### Requirement: Redirect и dispatch форварды
Форвард с `redirect="true"` SHALL выполняться как HTTP-редирект (новый запрос клиента); форвард с `redirect="false"` (по умолчанию) SHALL выполняться как dispatch внутри контейнера в том же запросе.

#### Scenario: Редирект
- **WHEN** форвард объявляет `redirect="true"` с путём `/Done.do`
- **THEN** клиент получает HTTP-редирект на этот путь

#### Scenario: Dispatch
- **WHEN** форвард объявляет `redirect="false"` с путём `/pages/Done.jsp`
- **THEN** клиент получает содержимое JSP в ответе того же запроса
