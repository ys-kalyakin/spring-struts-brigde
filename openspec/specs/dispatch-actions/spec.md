# dispatch-actions Specification

## Purpose

Семейство dispatch-экшенов (`org.apache.struts.extras.actions` эталона): один класс экшена обрабатывает несколько операций, выбирая метод по данным запроса.

## Requirements

### Requirement: Выбор метода по параметру
`DispatchAction` SHALL выбирать метод обработки по значению параметра, имя которого задано атрибутом `parameter` маппинга: запрос с `?method=save` вызывает метод `save(...)` с той же сигнатурой, что и `execute`, и его результат обрабатывается как обычный результат экшена.

#### Scenario: Диспетчеризация по method
- **WHEN** маппинг объявляет `parameter="method"`, и запрос содержит `?method=save`
- **THEN** вызван метод `save` экшена и его результат обработан как форвард

#### Scenario: Неизвестный метод
- **WHEN** запрос передаёт значение параметра, для которого метод отсутствует
- **THEN** обработка завершается ошибкой, сообщающей о невозможности диспетчеризации

### Requirement: Выбор метода по ключу сообщения
`LookupDispatchAction` SHALL выбирать метод по кнопке отправки: значение параметра (текст кнопки) переводится в ключ сообщения через карту `getKeyMethodMap()` и бандл, а ключ — в имя метода; тексты кнопок берутся из message-resources.

#### Scenario: Диспетчеризация по кнопке
- **WHEN** карта связывает ключ `button.save` с методом `save`, бандл содержит `button.save=Save`, и запрос отправлен с параметром кнопки `Save`
- **THEN** вызван метод `save`

### Requirement: Метод, заданный в маппинге
`MappingDispatchAction` SHALL вызывать метод, имя которого указано в атрибуте `parameter` маппинга: несколько маппингов на один класс ведут на разные методы.

#### Scenario: Два маппинга на один класс
- **WHEN** маппинги `/edit` и `/save` указывают на один класс с `parameter="edit"` и `parameter="save"`
- **THEN** запрос `/edit.do` вызывает метод `edit`, запрос `/save.do` — метод `save`

### Requirement: Событийная диспетчеризация
`EventDispatchAction`, а также `ActionDispatcher`/`EventActionDispatcher` (диспетчеризация для экшенов, не наследующих DispatchAction) SHALL выбирать метод по имени события в параметрах запроса: параметр, имя которого перечислено в атрибуте `parameter` и присутствует в запросе, задаёт метод (с поддержкой префиксных схем и значения по умолчанию `default`).

#### Scenario: Диспетчеризация по событию
- **WHEN** маппинг объявляет `parameter="save,cancel,default"`, и запрос содержит параметр `save`
- **THEN** вызван метод `save`

#### Scenario: Диспетчер без наследования
- **WHEN** экшен не наследует DispatchAction и использует `ActionDispatcher` с `parameter="method"`
- **THEN** метод выбирается по параметру запроса так же, как в DispatchAction

### Requirement: Метод по умолчанию
Если параметр диспетчеризации отсутствует в запросе, dispatch-экшен SHALL вызвать метод `unspecified(...)`, если он определён; иначе — ошибку диспетчеризации.

#### Scenario: Запрос без параметра метода
- **WHEN** запрос не содержит параметр `method`, и экшен определяет `unspecified(...)`
- **THEN** вызван метод `unspecified`
